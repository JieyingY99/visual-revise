# Visual Revise

在任意网页上用 Figma 式属性面板可视化改稿，一键导出 AI 能**精确定位**的提示词。

解决的问题：页面已经做完了，视觉细节不对，但「哪里不对、要改成什么样」用文字说不清。
以前要开 DevTools 找元素、试值、复制选择器、手写描述给 AI，AI 还得自己去代码里猜是哪个组件。

```
在真实网页上可视化改（拖布局 / 调间距 / 换字体 / 加评论）
    ↓ 改动自动累积成结构化记录
一键复制提示词  →  粘给 Claude Code / Cursor / Codex  →  AI 改代码
    或
导出 JSON      →  开发导入后逐项修
```

## 安装

首版不上 Chrome 应用商店，走开发者模式加载：

1. 构建产物

   ```bash
   npm install
   npm run extension
   ```

2. 打开 `chrome://extensions/`
3. 右上角打开 **开发者模式**
4. 点 **加载已解压的扩展程序**，选择本仓库的 `extension/` 目录
5. 在任意网页点击扩展图标，或按 `Alt+Shift+D`

> Chrome 137 起移除了 `--load-extension` 命令行开关，只能用上面的界面方式加载。

## 使用

唤起后页面顶部出现一条工具条，它是全部操作的入口：

```
◇ │ ✋  ▣  ▢  ⇅ │ ↺  ↻ │ ☰ 记录 ③   ⧉ 复制提示词 │ ✕
    └ 四个互斥模式 ┘           └──── 出口 ────┘
```

模式与撤销 / 重做只放图标，功能名与快捷键在 hover 气泡里。出口那两个保留文字——
它们是主要动作，只给图标会找不到。

- **浏览页面** `B` — 插件完全让开，页面照常点。工具条留着，随时切回来
- **选择元素** `V`（默认）— 点击页面元素，旁边出现属性面板
- **评论** `C` — 在元素上写 CSS 表达不了的交互需求，模式常驻，可连着标注
- **重排** `R` — 拖动 flex / grid 容器里的子元素调整顺序；面板换成结构树
- **记录** `L` — 打开改动列表，可回跳定位、单条撤销、导入导出 JSON
- **复制提示词** `P` — 把全部改动整理成提示词送进剪贴板

工具条可拖动。属性面板只在真正选中元素后出现，排版参照 Figma 的设计面板：
分区标题独立成行、字段标签在控件上方、成对字段并排两列（宽/高、上/右内边距等）、
输入框内嵌前缀标识。

分区顺序对齐 Figma 实测结果：

```
Position → Layout → Appearance → Typography → Fill → Stroke → Effects
```

`Typography` 的位置是实测 Figma Desktop 得来的——选中文本图层时它插在
`Appearance` 与 `Fill` 之间，而不是排在最后。它默认折叠，**选中文字元素时自动展开**。

**什么时候不显示它**：`<img>` / `<video>` / `<canvas>` / `<iframe>` 这类内容由外部资源
决定、自身不承载文字的元素，整个 `Typography` 分区连同 `color`、`overflow` 一起隐藏——
它们没有作用对象，留着只占位置。这一点与 Figma 一致（图片图层不渲染 Typography）。

内联 `<svg>` 刻意不在此列：它里面可以放 `<text>`，而且确实继承 `font-*`。

**什么时候保留**：普通容器仍然显示，哪怕它自己没有直接文字。这是与 Figma 的一处
刻意偏离——Figma 没有继承，而 CSS 里在容器上设 `font-size` 让子元素继承是常见写法，
隐藏它会让「给整张卡片调字号」无法表达。分区位置也固定不随选中变动，顺序跳来跳去
会毁掉肌肉记忆。

### Layout 按「排列方式」组织

不是一条 CSS 属性一行，而是先选排列方式，再按它决定显示什么——这是 Figma 的
Auto layout 面板的组织法：

```
排列    [自由] [纵向] [横向] [网格]   ⤶换行
尺寸    W [409 ] 填满⌄   H [412] 贴合⌄  🔗
对齐    [九宫格]        间隔 [10]        ← 仅 flex
网格    [3 × 自动]      间隔 [10] [10]   ← 仅 grid
内边距  [⊞ 24] [⊟ 16]  ⊡
外边距  [⊞ 20] [⊟ 20]  ⊡
☐ 裁剪内容
```

`display:block` 下不显示对齐与间隔——`justify-content` / `align-items` / `gap`
在那里根本不生效，留着控件只会让人以为改了有用。

**对齐九宫格**按屏幕方向（左中右 / 上中下）操作，写入时自动换算：`justify-content`
管主轴、`align-items` 管交叉轴，而主轴方向随排列方式变，纵向排列时两者要对调。

**间距是两段式**：默认只给「水平」「垂直」两个框，点 ⊡ 展开成四边独立。两边不等
时留空并提示「混合」——挑一个显示会让人以为两边相同，一敲回车就把另一边悄悄改了。

**尺寸有三种模式**，对应 Figma 的 Fixed / Hug / Fill：

| 模式 | 写进 CSS |
|---|---|
| 固定 | `width: 240px` |
| 贴合 | `width: fit-content` |
| 填满 | flex 主轴上 `flex: 1`；其余 `width: 100%` |

模式按钮点开还能添加最小/最大宽高——它们此前是常年空着的两整行。

**网格**点开是 12×12 点阵，拖出行列；底部「打开网格设置」进二级面板，逐条调
轨道类型（等分 / 固定 / 贴合 = `1fr` / `<length>` / `auto`）。

### Fill 随元素类型变形

Figma 的 Fill 是「这个图层被什么填充」的多态槽位：图片图层是那张图，文本图层是字色，
形状是背景色。CSS 把这三件事拆成了互不相干的属性，面板按元素类型决定谁排最前：

| 选中的元素 | Fill 第一行 |
|---|---|
| `<img>` / `<video>` | 图片预览（缩略图 + 天然尺寸 + 文件名）+ 换图按钮 |
| 有 `background-image` | 背景图预览 + 换图按钮 |
| 文字元素 | 字色（`color`） |
| 其它 | 背景填充（色 / 渐变） |

`color` 因此归入 Fill 而不是 Typography——这也是 Figma 的建模：文本图层的 `fills[0]`
就是字色。

鼠标悬停在面板或改动列表上时滚轮只滚动浮层本身，不会带动底下的页面。

| 快捷键 | 作用 |
|---|---|
| `Alt+Shift+D` | 唤起 / 关闭编辑器 |
| `Tab` | 切换编辑态 ↔ 交互态（验证 hover、点击等原生交互） |
| `B` | 浏览页面（插件让开，页面正常交互） |
| `V` | 选择元素（默认模式） |
| `C` | 评论模式（在元素上写交互需求，可连着标注多个元素） |
| `R` | 拖拽重排模式（在页面上直接拖动子元素调整顺序） |
| `L` | 开合改动记录 |
| `P` | 复制提示词 |
| `⌘Z` / `⌘⇧Z` | 撤销 / 重做（上限 100 步） |
| `Delete` | 删除选中元素（记录在案，可放回） |
| `Esc` | 逐层退出：草稿 → 模式 → 选中 |
| `↑` `↓` | 数值微调（按住 `Shift` 步进 10） |

`B` `V` `C` `R` 四个模式键是**幂等**的，不做 toggle：连按 `C` 一直停在评论模式，
正如 segmented control 里点两次「Work」不会跳回别处。退出某个模式靠按对应的那个键
（多半是 `V`）或 `Esc`。工具条上这四个按钮也长成一条 segmented control——
凹进去的轨道加一块滑块，滑块靠 `transform` 位移，切换时看得出是同一块东西移过去了，
而不是「这块灭、那块亮」。

这些单字母键都在捕获阶段被真正接管（`preventDefault` + `stopPropagation`）。

上游 VisBug 给它那 13 个工具各注册了一个单字母热键（`g i x l m p a v h d f e s`），
而它的工具条默认是隐藏的——按 `m` 会在背后切到 margin 工具、`f` 切到 font、
`h` 切到 hueshift，界面上没有任何提示，但**方向键从此就在改样式**。在页面上随手
打个字就可能中招。挂载时已把这批热键全部解绑；解绑的只是热键，工具本身仍可被
代码直调（浏览模式的停用/恢复走 `visbug.guides()`，双击进 text 工具走
`toolSelected()`），`⌘/Ctrl + /` 唤出工具条后点击也照常。

焦点落在面板内时只让出 `Tab` 与 `Esc`——它们在面板里有自己的语义（切焦点、
关弹窗）。不能整块让路：用鼠标点过工具条按钮后，焦点就停在 shadow DOM 里那个
button 上，整块让路会让此后所有快捷键失效，而「点按钮切模式、接着用键盘」
恰恰是最常见的操作顺序。

面板顶部还有 `⧉` 共享元素联动（改一个同步页面中所有同构元素）、折叠与关闭。

数值输入框左边的标签可以**横向拖动**调值，和 Figma 一样；聚焦后按 `↑` `↓` 微调，
`Shift` 加速十倍。opacity、z-index、font-weight 这类无单位属性不会被误加 `px`。

### Typography 紧凑排布

字体独占一行、字重与字号并排，都不带标签——内容本身就说明了是什么；只有行高与
字距需要标签，光看数字认不出是哪个。大小写与装饰线收在「更多」里。整个分区
5 行，改造前是每属性一行共 7 行。

### 跨重渲染：改动不会被框架清掉

记录挂的是 DOM 节点引用。React / Vue 这类框架重渲染时会把节点整个换掉，引用随之
悬空——所有挂在上面的改动会**静默消失**。用户看到的就是「点了一下侧栏开关，之前的
标注全没了」。

没有「切回来」这样一个可以挂钩子的时刻：重渲染发生在 hover、请求返回、任意一次
state 变化时。所以这里是**持续对账**：MutationObserver 一发现有增删就找回失联的记录，
按锚点重新绑定，并把改动重新贴到新节点上（光救回记录、不救画面等于没救）。

**「被换掉」和「被删掉」要的证据不一样**，所以候选分两个池子：

| | 需要的证据 | 依据 |
|---|---|---|
| 样式 / 文案 / 评论改绑 | **替换** | 新节点出现在「同一父节点刚失去过子节点」的位置 |
| 删除重放 | **重新出现** | 任何新增节点 |

少了这条区分，「删掉两行里的第一行」会被当成「第一行被换成了第二行」，改动就贴到
隔壁去了。此外还要求**身份**（标签 + 稳定类名 + 首条文本特征）一致——选择器里的
`nth-of-type` 定位的是位置，而删除本身就会让后面的兄弟节点整体前移一位。

**认不准就标成「元素已消失」，不猜。** 记录仍留在列表里（压暗显示），改动被冻结下来。
静默丢弃正是这个 bug 本身；而猜错比丢失更糟——导出的提示词会是错的，用户还发现不了。

页面如果坚持把删掉的元素渲染回来，重放到 30 次就停手并标成「页面在还原」，
不跟渲染循环死磕到页面闪烁。

### 浏览模式与面板摆位

**浏览模式**（`B`）把页面完全还给你：选择引擎暂停、覆盖层收起、评论 pin 也藏起来
（它们有 `pointer-events`，留着会挡住页面上那个位置的点击）。工具条留着，不然进去
就出不来了。

按键归谁，看工具条在不在：

| 状态 | 工具条 | 按键 |
|---|---|---|
| 浏览模式 `B` | 可见 | 归插件——tooltip 上印着这些键，按下去就得管用 |
| 隐身态 `Tab` | 隐藏 | 归页面——除 `Tab` 外一律放行 |

真正「把页面完全让给网站自己的快捷键」的是 `Tab` 隐身态：连工具条一起藏，
完全让开，再按一次回到原来的模式。Gmail、Notion 这类有单字母快捷键的站点，
要用它们自己的键就按 `Tab`。

浏览模式下还有一件事容易被忽略：VisBug 的 guides 工具会在 `mousemove` 里
执行 `gridlines.style.display = null`，光给覆盖层设 `display:none` 是没用的——
鼠标一动标尺线就浮回来。所以这里是**真正停用**上游工具，退出时再按原样装回。
两个面板的 `×` 都通向浏览模式——「我不改了，把页面还给我」。

**面板摆位**跟着选中的元素走：优先放在它右侧，右边塞不下就翻到左侧，纵向对齐元素
顶部，撞上工具条就压到它下面，最后一律夹回视口内。写死在右上角的话，选到页面右侧
的元素时面板正好盖住它——而改属性的全部意义就是看着它变。

只在换了元素时重算，不跟随滚动：面板是 `fixed` 的，滚一下就重算会让它一路乱跳。
手动拖过之后就不再自动摆位，直到你收起面板。

一个固有的代价：横排的卡片里选中一张，面板会盖住它右边的邻居。贴着元素放和不挡住
邻居这两件事无法同时满足，这里选了前者。

### 重排：结构树

重排模式关心的是「这个元素在结构里的哪个位置」，不是它有什么属性，所以它有自己的
面板——一棵图层树，取代属性面板出现在同一个位置。

```
∨ Section                    section
  ∨ Article                  article
      Frame                      div
      Heading  “Original Thinking”  h2
      Text     “Custom Rose Trail”  span
  › Article                  article
```

每行是：折叠箭头 · 语义名 · 文字预览 · 右侧灰色的真实标签名。`div` / `span` 本身
没有语义，按它实际扮演的角色命名——横排的容器叫 Row、竖排叫 Column、只裹着一段
文字的叫 Text。比清一色的「div」有用得多。

默认**只展开到选中项那条路径**，其余全部折叠：真实页面动辄几千个节点，一次铺开
既卡又找不着人。单层超过 200 个折叠成一行提示。

点行 = 在页面上选中它；hover 行 = 页面上高亮那个元素；**拖动行 = 排序**。

树里拖和页面上直接拖走的是同一个 `applyOrder`，两个入口写出的记录才一致。排序落在
CSS `order` 上，所以树按**视觉顺序**列子元素而不是 DOM 顺序——否则拖完树里纹丝不动，
看起来像没生效。一次拖拽合成一条历史，⌘Z 整体退回去，而不是一个兄弟一步地往回倒。

只能在同一个父节点内换位：跨父节点搬家要真的动 DOM 结构，改动模型记录不了那个。

### 图片：换图与参考图

两处入口，共用同一条通路：

- **换图** — 选中图片元素，点 Fill 分区里的换图按钮，挑一张本地图
- **参考图** — 评论气泡输入框左下角的 `+`，或直接**粘贴截图**、把图**拖进气泡**

图片会以 **chip 的形式插在光标处**，像一个字符一样待在句子里：「这块 [图片] 换成
[图片] 的处理」。这比只在下方列一堆附件多说了一件事——**图指的是句子里的哪一处**。
chip 上只有 16px 缩略图，hover 会弹出大图；Backspace 一次删掉整块，对应的说明条目
跟着消失，反过来也一样，两边不会各说各话。

下方的说明区每张图可以单独写一句（AI 拿到「这张图说明什么」才知道该看图里的哪部分），
超过五张就自己滚动，不会把气泡撑出屏幕。

保存时 chip 序列化成 `[图1]`、`[图2]`，提示词里的参考图清单用同一套编号，
AI 既知道图插在句子的哪个位置，也知道该去读哪个文件。

只有图、没写文字的评论同样能保存——「照这张改」本身就是需求。

**图片是怎么交到 AI 手里的**：剪贴板一次只能带纯文本或一张图，带不了「文本 + 多张图」；
base64 内联又会把提示词撑到没法粘贴，多数 AI 也不解析提示词里的 data URI。所以走
「落盘 + 绝对路径」——复制提示词时把图写进下载目录的 `visual-revise-refs/<时间戳>/`，
正文里只写路径，AI 自己去读图：

```markdown
## 交互备注

- **「Get started」**
  - 选择器：`button.btn.btn-primary`
  - 需求：悬停时整卡上浮 4px，阴影照 [图1] 的强度
  - [图1] `/Users/you/Downloads/visual-revise-refs/2026-09-01-134500/01-hover-state.png` —— 目标 hover 效果

> 参考图是用户想要的目标效果，请先用读图工具打开看过再动手。
> 需求文本里的 `[图1]`、`[图2]` 指的就是紧随其后列出的同号参考图——
> 用户把图插在句子的哪个位置，说的就是那一处。
```

落盘有两条路，运行时自适应：扩展通道（`chrome.downloads`）能查回**真实绝对路径**；
拿不到时退回页面下载，路径只能按默认下载目录推测，此时提示词里会明确标注
「路径为推测」。**绝不能让 AI 拿着一个看似确切、实则不存在的路径去读图**——
那会让它报错，或者干脆编造图片内容。复制后的 toast 会告诉你走的是哪条路。

页面若禁用了 `img-src data:`（CSP），缩略图会退化成「类型 + 体积」的文字条目，
换图后画面也不会更新——但改动记录与提示词不受影响，工具会 toast 说明这一点。

## 提示词为什么能让 AI 定位准

导出的提示词对每个元素给出多重锚点：

```markdown
**定位**
- 选择器：`section.cards > article.curve-card:nth-of-type(2)`
- 标签：`<article class="curve-card">`
- 文本特征：`"Thinking Five"` `"Custom Rose Trail"`
- DOM 路径：`body > section.cards > article.curve-card`
- 位置：同级第 2 个（共 3 个），紧邻「Original Thinking」之后

**改动**

| 属性 | 原值 | 新值 |
|---|---|---|
| padding | `15px` | `24px` |
| border-radius | `18px` | `12px` |
```

关键是**文本特征**排在选择器之后但优先级最高：Tailwind、CSS Modules、CSS-in-JS 都会改写类名，
选择器里的 `_curveCard_x8f2a` 在源码中根本不存在，而 `"Thinking Five"` 一搜就能命中组件文件。

`tests-e2e/locate.mjs` 用一个类名全部哈希化的 React 项目量化验证了这一点。

改动捕获用「快照 + diff」：元素首次被选中时记录原始 inline style 与计算值，
导出时对比得出真正改了什么。因此不必侵入上游的 20 多个 feature，
面板改的、快捷键改的、拖拽改的都能被同一套机制捕获，撤销也天然成立。

## 与 VisBug 的关系

本项目 fork 自 [GoogleChromeLabs/ProjectVisBug](https://github.com/GoogleChromeLabs/ProjectVisBug)（Apache-2.0）。

上游提供了跨页面注入、元素选择引擎、Shadow DOM 隔离、样式读写、间距测量等基础能力。
本项目在其上新增：Figma 式属性面板（分区顺序、Layout 的 Flow 组织、Fill 多态、尺寸模式与网格设置均对齐 Figma 实测）、删除记录与还原、改动记录与撤销、AI 提示词导出、评论标注与参考图、图片替换、
共享元素联动、拖拽重排、JSON 导入导出。

对上游文件的修改仅三处，均为必要的能力缺口：

- `app/utilities/common.js` — `isOffBounds` 增加穿透 shadow 边界的追溯（原实现的 `closest` 不跨 shadow root，会把本扩展自己的 UI 当成页面元素选中）
- `app/features/selectable.js` — 导出可逆的 `pause` / `resume`（原 `disconnect` 单向不可恢复），
  释放 `Tab` 键给编辑态切换，并把绑定/解绑收敛到同一份 `HOTKEYS` 清单
  （原先两处手写已经漂移，导致每次 resume 累积一批快捷键处理器）
- `app/components/vis-bug/vis-bug.element.js` — 三行挂载调用
- `extension/visbug.js`、`extension/toolbar/{inject,restore}.js`、
  `extension/contextmenu/{colormode,colorscheme}.js` — service worker 相关修复：
  向尚未注入编辑器的标签页 `sendMessage` 会抛 `Could not establish connection`
  并冒成 Uncaught；`tabs.onUpdated` 未按 `changeInfo` 过滤会让状态机与页面脱节，
  导致在已有编辑器的页面上重复注入。改为静默忽略「无接收方」、注入后再发消息、
  仅在真正导航时重置状态，并以页面里是否已有 `<vis-bug>` 作幂等判据。

新增代码全部隔离在 `app/core/` 与 `app/components/{props-panel,change-list,comment-layer}/`，便于日后 rebase 上游。
