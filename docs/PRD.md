## 0. 产品定位

在**任意网页**上做可视化改稿，最终产出一段 **AI 能精确定位到源码的提示词**。

它不是设计工具，也不是 DevTools 的替代品。它解决的是这样一件事：
产品或设计看着线上页面说「这里间距大了、这个字重不对、这块要能 hover 上浮」，
而这些话传到工程师那里时，既没有确切的元素定位，也没有确切的数值。

边界：
- 所有改动只发生在**当前页面的运行时**，不写回源码、不持久化到服务器
- 刷新页面即全部消失（改动可导出为 JSON 带走）
- 面向的是「描述清楚要改什么」，不是「改完就上线」

| AC | 验收标准 |
|---|---|
| AC-1.1 | 点击扩展图标可唤起编辑器；再点一次收起 |
| AC-1.2 | `Alt+Shift+D` 与点击图标等价 |

## 2. 模式体系

四个互斥模式，外加一个隐身态。工具条上是一组 segmented control。

| 模式 | 键 | 做什么 |
|---|---|---|
| 浏览 | `V` | 把页面交还给用户，正常点击、滚动、交互 |
| 选择 | `A` / `F` | 默认模式。`A` 落到面板的「选择元素」tab，`F` 落到「结构」tab |
| 评论 | `C` | 点击元素写下交互需求，可连续标注多个 |

**重排不再是模式**：结构树并入属性面板的「结构」tab，同一个元素的属性与它在
结构里的位置在一处看。页面上直接拖子元素的能力保留，跟着「结构」tab 开关。

| AC | 验收标准 |
|---|---|
| AC-2.1 | 四个模式键切换正确，工具条高亮跟随 |
| AC-2.2 | 模式键**幂等**：连按 `C` 一直停在评论模式，不 toggle 回选择态 |
| AC-2.3 | 浏览模式下点击页面元素不会被选中，页面自身的交互正常工作 |
| AC-2.4 | 浏览模式下评论 pin 隐藏——它们有 `pointer-events`，留着会挡住该位置的点击 |
| AC-2.5 | 浏览模式下工具条保留，否则进去就出不来 |
| AC-2.6 | 浏览模式下移动鼠标不会画出任何标尺线 / 测距线 |
| AC-2.7 | `Tab` 进入隐身态：连工具条一起藏，再按一次回到原模式 |
| AC-2.8 | 隐身态下除 `Tab` 外所有按键放行给页面（此时用户在用这个网站，不能占着单字母键） |
| AC-2.9 | `Esc` 从任何模式回到选择态 |
| AC-2.10 | 属性面板与结构树的 `×` 都只收起自己那块 UI，**不改变当前模式**——用户多半还想接着做同一件事；关闭整个编辑器是工具条上那个 `×` 的事 |
| AC-2.12 | 结构是面板里的一个 tab 而非模式：`F` 打开、`A` 切回，当前模式始终是「选择」 |
| AC-2.13 | 面板只在选中元素后出现，因此未选中时没有结构树入口 |
| AC-2.14 | 「结构」tab 打开时启用页面直接拖拽；切回「选择元素」tab 则关闭 |
| AC-2.15 | 深层嵌套不撑爆面板：宽度恒为 300，标题栏与 tab 不被挤出视口，树可纵向滚动、横向滚动 |
| AC-2.16 | 拖拽进行中按 `Esc` 取消这一次拖拽，不落下任何 `order` |
| AC-2.17 | 共享元素开启时，在结构里重排会同步到每个同构容器（按下标映射） |
| AC-2.11 | 切换模式不会丢失已有的改动记录 |

## 4. 快捷键

分三层，冲突时按这个顺序裁决：

1. **修饰键组合**（`⌘Z` 等）—— 在最前面处理，不受模式影响
2. **本插件的单字母键** —— 仅在工具条可见时归插件
3. **页面自己的键** —— 隐身态下全部放行

| AC | 验收标准 |
|---|---|
| AC-4.1 | `⌘Z` / `⌘⇧Z` 撤销重做（Windows 上 `⌘Y` 也认） |
| AC-4.2 | 在输入框里打字时，单字母键不触发插件功能，字符正常输入 |
| AC-4.3 | 在输入框里 `⌘Z` 让路给浏览器的文本撤销，不撤掉整次改稿 |
| AC-4.4 | 焦点停在插件面板内（例如刚点过工具条按钮）时，单字母快捷键**仍然可用** |
| AC-4.5 | 面板内的 `Tab` 与 `Esc` 归面板（切焦点、关弹窗），不被插件抢走 |
| AC-4.6 | 上游 VisBug 的 13 个工具热键（`g i x l m p a v h d f e s`）已解绑，不会在背后切换工具 |
| AC-4.7 | `L` 开合改动记录、`P` 复制提示词 |
| AC-4.8 | `Delete` / `Backspace` 删除选中元素，且只删一个（不触发上游的重复回调） |

## 5. 面板摆位

面板固定在一个地方，位置只由用户决定。早先的版本按选中元素的矩形算左右侧，
本意是别盖住正在改的东西，结果每换一个元素面板就跳一次——眼睛每次都得重新
找它，比偶尔被挡住更累。

| AC | 验收标准 |
|---|---|
| AC-5.1 | 属性面板固定出现在同一个位置（默认右上、工具条下方），**不**跟着选中的元素移动 |
| AC-5.2 | 拖动面板后位置记进 `localStorage`；换选元素、关掉面板再打开、刷新页面重新注入，都回到那个位置 |
| AC-5.3 | 任何情况下面板都不会超出视口：拖动时实时夹取，窗口变小后挤回视口内，重新拉大时回到记住的位置 |
| AC-5.4 | 默认位置不与工具条重叠（横排、竖排都是） |
| AC-5.5 | `localStorage` 被禁（无痕窗口 / 站点策略）时读写都不抛，面板退回默认位置照常可用 |
| AC-5.6 | 结构 tab 打开时面板仍在视口内 |
| AC-5.7 | 滚动页面时面板**不**跟着动（它是 fixed 的） |

| AC-5.8 | 工具条可在横排 / 竖排之间切换（第一格那个按钮），选择记在 localStorage，下次注入沿用 |
| AC-5.9 | 竖排时按钮文字收进 hover 气泡，气泡从按钮下方挪到右侧 |
| AC-5.10 | 竖排时分段控件的滑块沿纵轴移动，仍贴合当前模式 |

**已知取舍**：位置存的是页面自己的 `localStorage`，所以记忆按站点隔离——
在 A 站拖过的位置不会带到 B 站。bundle 以 `<script type="module">` 插进页面、
跑在主世界，够不着 `chrome.storage`；为一个坐标再搭一条
主世界 → content script → background 的消息通道不划算。

## 6. 属性面板（逐控件）

面板分 7 组。每个控件操作后必须**立刻**落到元素的 inline style 上，并进入改动记录——
这是整个工具的产出通道，任何一处"看起来改了、其实没写"都是最坏的 bug。

| AC | 验收标准 |
|---|---|
| AC-6.1 | Position：定位下拉写 `position`；X / Y 写 `left` / `top`；旋转写 `rotate`；层级写 `z-index`；X 前缀可横向拖着调值 |
| AC-6.2 | Layout 排列：四个分段各写 `display`（block / flex+column / flex+row / grid）；换行钮切 `flex-wrap` |
| AC-6.3 | 尺寸：W / H 输入写 `width` / `height`；比例锁开着时改 W，H 按锁定时的比例跟着变 |
| AC-6.4 | 对齐九宫格：点 (col,row) 写 `justify-content` / `align-items`，三档为 flex-start / center / flex-end |
| AC-6.5 | 间隔写 `gap` |
| AC-6.6 | 内 / 外边距：两段式输入分别写左右对、上下对；展开钮后四个方向各自可写 |
| AC-6.7 | 裁剪内容：勾上写 `overflow: hidden`，取消是**清掉声明**而不是写 visible |
| AC-6.8 | Appearance：不透明度写 `opacity`，圆角写 `border-radius` |
| AC-6.9 | Typography：字体下拉只换栈首；字重下拉、字号、行高、字距各写对应属性；对齐四段写 `text-align`；「更多」展开后 `text-transform` / `text-decoration-line` 可写 |
| AC-6.10 | Fill：可增删的**多层**填充列表。`background-image` 收逗号分隔的多层（第一层画在最上），`background-color` 垫底；纯色进不了 image 那一栏，除最底层外一律写成 `linear-gradient(c, c)` |
| AC-6.10a | 每层一行：色块 / 色值 / 不透明度 / 眼睛 / 减号。渐变和图片没有单一色值也没有单层不透明度（CSS 没这东西），那两格对它们只读 |
| AC-6.10b | 填充弹层四格里做三格：纯色 / 渐变 / 图片（只有「从电脑上传」）。**视频不做**——`url(x.mp4)` 语法过得去但画面出不来，`element()` 只有 Firefox 认，真要做只能往元素里插 `<video>` 子层，那是改 DOM 不是改样式 |
| AC-6.10c | 文字色是文本元素的主填充，跟填充层同形、也能用眼睛关掉；但它是 `color` 这条独立属性，删不掉，所以没有减号 |
| AC-6.16 | 每个颜色控件都有**色值**和**不透明度**两个独立输入；改色值不会把已调好的不透明度重置回 100% |
| AC-6.17 | 色盘 / 填充等弹层始终夹在视口内，内容变高（如切到渐变）后重新让位 |
| AC-6.11 | Stroke：颜色 / 宽度 / 样式各写 `border-*`；box-sizing 分段写 `box-sizing` |
| AC-6.11a | 没有描边时是空状态，只剩标题和加号——那三行描述的是一条并不存在的边 |
| AC-6.11b | 描边**只能一条**，加过之后加号置灰。实测 `border-image-source` 不吃逗号多层（写两层整条声明作废），而且它一旦非 none 就取代颜色绘制，跟 `border-color` 也叠不起来 |
| AC-6.12 | Effects：可增删的效果列表，加号弹出七种。三个直接写 CSS 原值的输入框已去掉——一个框里塞着 `rgb(255,255,255) 0 0 0 0, rgba(147,…` 既读不出有几条阴影，也没法单独关掉其中一条 |
| AC-6.12a | 七种的 CSS 落点：内阴影→`box-shadow: inset`、投影→`box-shadow`、图层模糊→`filter: blur()`、背景模糊→`backdrop-filter: blur()`、噪点/纹理→SVG `feTurbulence` 转 data URI 当 `background-image` 的一层、玻璃→`backdrop-filter: blur() saturate()` + inset 高光 |
| AC-6.12b | 同一种可以加多条，填充层和效果列表都可拖拽排序（`background-image` 的层序决定遮挡，`box-shadow` 的多条和 `filter` 的多函数也都有序）。**已知限制**：效果读回的顺序按 CSS 属性分组，跨属性的先后在 CSS 里没有记录、还原不出来；同一条属性内部的顺序保留，而那正是顺序真正影响渲染的地方 |
| AC-6.12b1 | 拖拽用 pointer 事件而不是 HTML5 `draggable`：行里铺满了 `<button>`，按在它上面浏览器根本不发 `dragstart`；而且原生拖放在自动化里驱动不了——CDP 的鼠标事件不会让浏览器合成拖放。指针捕获推迟到越过 4px 才生效，否则会把后续 click 的 target 重定向到整行，色块和参数面板就点不开了 |
| AC-6.12c | 每种效果的参数面板只列 CSS 真的做得到的几项。**Figma 的 Glass 只做得到近似版**：Refraction / Depth / Dispersion / Frost / Splay 是它渲染器里的折射运算，CSS 没有任何东西对得上；Shader 需要 WebGL 或 Houdini，不做 |
| AC-6.12d | 噪点/纹理与填充层共用 `background-image`：效果层排在前面（画在填充之上），填充解析时按 data URI 里的记号跳过它们，两边不会互相吞掉 |
| AC-6.22 | Fill / Stroke / Effects 三个分区**空状态也渲染**（标题 + 加号）——加号是添加第一条的唯一入口，整个分区不出现的话用户无从下手 |
| AC-6.23 | 这三个分区标题右侧：加号常驻，「绑定变量」鼠标进标题栏才出现（Figma 的 default / hover 两态）。分区级眼睛下放到每一行 |
| AC-6.23a | 「绑定变量」常驻显示（平时压暗，鼠标进标题栏提亮）。Figma 是 hover 才显形，但它那儿标题栏没有别的按钮；这里藏起来只会在加号左边留一个等宽的空洞，看着像图标没加载出来 |
| AC-6.23b | 在收起的分区上点加号会自动展开——加了东西却看不见，点下去像是没反应 |
| AC-6.24c | 绑了变量的格子换成一整块 chip（圆点 + 变量名），不再有可编辑的色值和不透明度——绑了变量，色值就该去改那个变量。判定读 **inline 原文**，`getComputedStyle` 会把 `var()` 解析成最终颜色，从它身上看不出绑定 |
| AC-6.24d | hover 时 chip 右侧出现 unlink；点它用当前解析出的实际颜色顶替 `var()`——绑定断开、画面不变，这是 Figma 那个 unlink 的语义，不是「清空这一格」 |
| AC-6.24e | 变量菜单按值的类型过滤：挑颜色时只列颜色变量，字体栈、`12px`、纯数字都不出现——点了也 apply 不上，只是让人在几十项里多翻几屏 |
| AC-6.24b2 | `Esc` 能关掉菜单。面板的 Esc 分支只是「有弹层时让路」，让完之后原先没有人接手 |
| AC-6.24b | 在菜单内部滚动不会把菜单关掉。全局的 `scroll` 监听在 capture 阶段收所有滚动，包括菜单自己的；变量列表有几十项、自带滚动条，一滚就关等于只能选到最上面几项 |
| AC-6.24 | 绑定变量写的是 `var(--x)`。**诚实的边界**：面板读 computed，而 computed 会把 `var()` 解析成最终值，所以面板上看不出它绑着变量；真正留住这层关系的是 inline style 和改动记录，导出的提示词里也是 `var(--x)` 而不是一个死色值 |
| AC-6.13 | 以上每一次写入都进改动记录（记录数递增），且面板标签变成"已改"色 |
| AC-6.14 | 分组标题上的「重置本组」只在该组改过时出现，点了把本组全部还原；「临时关闭本组」可开关 |
| AC-6.15 | Typography 与 Effects 默认折叠，减少首屏噪音；选中**文字元素**时 Typography 自动展开 |
| AC-6.18 | 「临时关闭本组」关掉的属性跟着该组**这次真的渲染出来的字段**走：选中直接承载文字的元素时 Fill 首行是字色，关组要连字色一起关（只关背景等于没关，这类元素本就没有背景）；纯容器则不动 `color`——那一行没渲染，且 `color` 会继承进整棵子树 |
| AC-6.19 | 填充控件在**纯色**态下与文字色控件同形：色值、不透明度两个可直接编辑的输入，色块与输入框尺寸逐项相同；其余三态（无填充 / 渐变 / 背景图）没有单一色值可填，退回只读摘要标签 |
| AC-6.20 | 颜色类控件点输入框是敲值、不弹色盘（事件跨 shadow 边界会把 `target` 重定向到 host，得看 `composedPath`）；点色块才开弹层 |
| AC-6.21 | 面板里每个图标按钮的图标在按钮方框内水平垂直都居中（`<button>` 的 UA `padding: 1px 6px` 必须显式清掉，否则 border-box 下内容盒被压窄、图标溢出后居中退化成左对齐） |

## 7. 内容操作

改的不只是样式：文案、图片、元素本身的去留和位置，都要能改、能记、能撤、能导出。
「位置」是真的搬 DOM 节点，不是写 CSS `order`——后者只改视觉顺序，DOM 顺序不变，
键盘 Tab 与读屏顺序会和用户看到的对不上，跨父级更是做不到。

| AC | 验收标准 |
|---|---|
| AC-7.1 | 文案：进入编辑态后键入，改动作为「文案改动」单独记录，不混进样式属性；撤销可回到原文 |
| AC-7.2 | 换图：图片元素的 Fill 组有换图按钮，选文件后 `src` 变成新图；背景图元素走 `background-image` 通道；记录里不被 dataUrl 撑爆 |
| AC-7.3 | 删除：`Delete` 删掉选中元素，记录里留下标签 / 文本特征 / 子元素数；能从记录放回原位；放回后记录消失 |
| AC-7.4 | 页面拖拽移动：任意 tab 下按住页面元素拖动 ≥4px 即可移动，落点分「插到它前面 / 后面 / 放进它里面」三档，真的搬 DOM 节点、不写 `order`；中途 Esc 取消不留任何改动 |
| AC-7.4b | 起拖阈值：按下不动就松开仍然是「选中」，不会变成一次移动——拖拽不再需要先切到某个 tab |
| AC-7.5 | 结构树移动：树里拖行同样是搬 DOM，落点同样分三档；放进折叠着的容器会自动展开它 |
| AC-7.6 | 共享元素：开启后改一处，结构相同的兄弟同步；面板显示「联动 N 个」；关闭后只改选中项 |
| AC-7.7 | 跨容器：页面上和树里都能把元素拖进**任意**容器（不限 flex/grid、不限同一个父级）；不能拖进自己或自己的后代，也不能拖到 `<html>` 下 |
| AC-7.8 | 移动可撤销：⌘Z 一次退回整次移动，⌘⇧Z 重做；把元素拖回原位后，改动记录里那一条自动消失 |
| AC-7.9 | 共享联动的边界：同一个父级里换位会按下标同步到同构容器；跨容器移动只作用于当前元素，并给出提示 |
| AC-7.10 | 跨重渲染：框架把源容器整块重渲染后，移动被重放——页面上只留一份，不会「原位一个、新家一个」；目标容器失联时记录留着并标明 |

## 8. 记录与导出

工具的终点是一段 AI 能拿去改源码的提示词。记录必须完整、可回退、可带走。

| AC | 验收标准 |
|---|---|
| AC-8.1 | 改动记录列表：按元素分组，属性 / 文案 / 评论 / 删除各自有计数；hover 列表项在页面上高亮该元素 |
| AC-8.2 | 单条撤销：列表里可撤销某一条属性改动，其它改动不受影响 |
| AC-8.3 | 撤销 / 重做栈：不同属性各自入栈；一次拖拽 / 切排列是一个动作，⌘Z 整体退回 |
| AC-8.4 | 评论：评论模式点元素弹输入框，保存后页面出 pin 并编号；点 pin 可编辑；可删除 |
| AC-8.5 | 参考图：评论里可通过选文件 / 粘贴 / 拖拽加图，逐张移除，带说明一起保存 |
| AC-8.6 | 提示词：包含元素定位、属性改动、独立的「文案改动」「移动的元素」「删除的元素」「图片替换」段落，以及摘要计数。移动那一段的 from / to 两头都给出容器选择器 |
| AC-8.7 | JSON：导出带 schema 版本；导入后改动重新应用到页面、记录数一致 |
| AC-8.8 | 跨重渲染：框架把节点整个换掉后，改动一帧内重新找回并施加到新节点；不会贴到长得一样的邻居上 |
| AC-8.9 | 重置：清掉所有记录（含已失联的），页面恢复——包括把搬过家的元素放回原位；⌘Z 能把这次重置连同移动一起救回来 |

## 9. 面板 UI 一致性

前面几节都在问「功能对不对」，这一节只问「长得对不对」。功能全绿的界面照样
可以是歪的——本批就是这么抓到「眼睛和减号被挤出面板右边界」的：按钮还在、
点击也有效，只是画到了看不见的地方，所有功能断言都照常通过。

| AC | 验收标准 |
|---|---|
| AC-9.1 | 面板里每个图标都是 1:1（`svg` 的宽高相等、`viewBox` 是正方形），没有被拉扁的 |
| AC-9.1b | 图形本身落在 viewBox 中央（墨迹中心偏移 ≤ 0.6）。这是前一条盖不住的盲区——宽高比和 viewBox 都对，路径照样可以画偏，在 24px 的按钮里就是肉眼可见的歪。量的是 **svg 根节点**的 `getBBox()`：逐个子元素取再合并是错的，那返回各自局部坐标系的边界，外层 `<g transform>` 的平移根本看不见 |
| AC-9.1c | 同一上下文（同一行 / 同一分段 / 同一 acts 组 / 输入框前缀）里图标渲染尺寸一致。现行档位：标题栏与 flow 分段 14、按钮 13、输入框前缀 12。换行钮 13 挤在四个 14 的分段旁边就是小一号 |
| AC-9.1d | 图标墨迹占 viewBox 的 60–80%。同样 13px 的按钮里，眼睛原来画满 88%、加号只画 56%，视觉大小差近一倍；统一后偏小的放大到 10/16，偏大的缩到 12/16 |
| AC-9.2 | 同一行里输入类控件等高。图标按钮不参与——它本来就比输入框矮，Figma 也是这样 |
| AC-9.2b | 同一行里所有控件（含图标按钮）垂直居中，中心线偏差不超过 1px |
| AC-9.2c | 同一个层列表里每行等高 |
| AC-9.2d | 颜色类控件（`vr-color` / `vr-fill`）在面板各处同高——它们在界面上就是同一种东西 |
| AC-9.2f | 所有输入类控件外框统一 **32px、`box-sizing: border-box`**。原来是两套：带 1px 透明边框的（颜色控件 / `resize-cell`）外框 32，不带的（`input` / `segment` / `vr-select`）外框 30——内容高都是 30，差在边框。两套并存时四行并排的按钮列宽跟着差 2px，两列的分界线就错开 |
| AC-9.3 | 同类容器的间距只有一个值，不是每处一个数 |
| AC-9.4 | 没有元素被挤出面板的左右边界（flex 子项缺 `min-width: 0` 时最容易发生） |
| AC-9.5 | 面板与工具条在每个阶段都完整落在视口内，含窄视口 900×640 |
| AC-9.6 | 默认态与选中态的文字、图标都达到 WCAG AA：正文 4.5:1，图标和大字 3:1。半透明前景先合成到底色再算——`opacity: .3` 的灰按钮不能按不透明来判 |
| AC-9.7 | 悬停态同样达标。hover 的颜色写在 CSS 伪类里读不出来，只能真的悬上去再量 |
| AC-9.2e | 并排的图标按钮是**正方形**——只拉高不拉宽会得到 24×32 的长方形，比不拉更难看；宽度用 `aspect-ratio: 1` 跟着行高走 |
| AC-9.9 | 面板左右内边距对称，滚动条不占位。原生滚动条会占 10px 布局宽度把右边挤窄；headless 用 overlay 滚动条量不出，用户的 macOS 一开「始终显示滚动条」就露馅。设计工具面板惯例不显示常驻滚动条 |
| AC-9.10 | 并排行内的间距只有一个值（6px）。原来 grid 行 8、flex 行 6、层列表 4 三种混用，上下两行的间距一眼看得出不一样 |
| AC-9.11 | 每行最右的控件贴到行容器右边缘、不溢出。grid 行的按钮列写死 `24px` 时，按钮被 `aspect-ratio` 拉成 30/32 就探出网格 6~8px，右边缘跟上一行对不齐；改 `auto` 跟着行高走 |
| AC-9.8 | 七种效果的参数面板逐个打开检查：弹层内无元素越界、各行输入区的左右边缘对齐成一列、输入框里的值不被框宽截断（量 `scrollWidth`）、弹层自身在视口内 |

检查覆盖四个场景：属性 tab 全部展开、填充两层 + 效果四条、结构 tab、窄视口；
外加七种效果的参数面板各开一次。

**由此改掉的**：`--vr-label` 从 `#9b9b9b` 调到 `#a6a6a6`。前者在字段底色 `#383838`
上只有 4.22:1（分段控件未选中项的文字正好落在这个组合上），差一点到 4.5:1；
后者在两种底色上分别是 4.82:1 和 5.74:1。

**检查器的两个坑**（都在注释里记了）：折叠箭头这类元素是 `background: currentColor`
加 `clip-path` 切出来的图形，拿 `color` 当前景会算出 1:1——因为那正是它的背景，
这类空元素要改用自身背景当前景、父级当底色；`opacity` 作用在整个元素上，
等价于把前景按该比例合成到背景，不折算进去会把压暗的按钮判成清晰可见。
