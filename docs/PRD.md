## 0. 产品定位

在**任意网页**上做可视化改稿，最终产出一段 **AI 能精确定位到源码的提示词**。

它不是设计工具，也不是 DevTools 的替代品。它解决的是这样一件事：
产品或设计看着线上页面说「这里间距大了、这个字重不对、这块要能 hover 上浮」，
而这些话传到工程师那里时，既没有确切的元素定位，也没有确切的数值。

边界：
- 所有改动只发生在**当前页面的运行时**，不写回源码、不持久化到服务器
- 刷新页面即全部消失（改动可导出为 JSON 带走）
- 面向的是「描述清楚要改什么」，不是「改完就上线」

| AC | 验收标准 |
|---|---|
| AC-1.1 | 点击扩展图标可唤起编辑器；再点一次收起 |
| AC-1.2 | `Alt+Shift+D` 与点击图标等价 |
| AC-1.3 | 收起后再次唤起，之前的改动记录仍在（同一标签页内） |

## 2. 模式体系

四个互斥模式，外加一个隐身态。工具条上是一组 segmented control。

| 模式 | 键 | 做什么 |
|---|---|---|
| 浏览 | `V` | 把页面交还给用户，正常点击、滚动、交互 |
| 选择 | `A` / `F` | 默认模式。`A` 落到面板的「选择元素」tab，`F` 落到「结构」tab |
| 评论 | `C` | 点击元素写下交互需求，可连续标注多个 |

**重排不再是模式**：结构树并入属性面板的「结构」tab，同一个元素的属性与它在
结构里的位置在一处看。页面上直接拖子元素的能力保留，跟着「结构」tab 开关。

| AC | 验收标准 |
|---|---|
| AC-2.1 | 四个模式键切换正确，工具条高亮跟随 |
| AC-2.2 | 模式键**幂等**：连按 `C` 一直停在评论模式，不 toggle 回选择态 |
| AC-2.3 | 浏览模式下点击页面元素不会被选中，页面自身的交互正常工作 |
| AC-2.4 | 浏览模式下评论 pin 隐藏——它们有 `pointer-events`，留着会挡住该位置的点击 |
| AC-2.5 | 浏览模式下工具条保留，否则进去就出不来 |
| AC-2.6 | 浏览模式下移动鼠标不会画出任何标尺线 / 测距线 |
| AC-2.11 | 标尺线（`visbug-gridlines`）、拖出的参考线、测距线本体都是 **50% 透明**：实色的线正好压在元素边缘上，看不清底下的东西；测距线上的数字标签保持实色，要读得清 |
| AC-2.7 | `Tab` 进入隐身态：连工具条一起藏，再按一次回到原模式 |
| AC-2.8 | 隐身态下除 `Tab` 外所有按键放行给页面（此时用户在用这个网站，不能占着单字母键） |
| AC-2.9 | `Esc` 从任何模式回到选择态 |
| AC-2.10 | 属性面板与结构树的 `×` 都只收起自己那块 UI，**不改变当前模式**——用户多半还想接着做同一件事；关闭整个编辑器是工具条上那个 `×` 的事 |
| AC-2.12 | 结构是面板里的一个 tab 而非模式：`F` 打开、`A` 切回，当前模式始终是「选择」 |
| AC-2.13 | 面板只在选中元素后出现，因此未选中时没有结构树入口 |
| AC-2.14 | 「结构」tab 打开时启用页面直接拖拽；切回「选择元素」tab 则关闭 |
| AC-2.15 | 深层嵌套不撑爆面板：宽度恒为 300，标题栏与 tab 不被挤出视口，树可纵向滚动、横向滚动 |
| AC-2.16 | 拖拽进行中按 `Esc` 取消这一次拖拽，不落下任何 `order` |
| AC-2.17 | 共享元素开启时，在结构里重排会同步到每个同构容器（按下标映射） |
| AC-2.11 | 切换模式不会丢失已有的改动记录 |
| AC-2.10a | 结构树头部不再有关闭 ×，收起这块 UI 归属性面板标题栏的 ×（不留派发后无人监听的死控件） |
| AC-2.10b | 在结构树里点一行选中：列表不滚、那一行留在原位。面板每次重建会把树摘下来再挂回，而「取消选中」那一步面板先被 hidden，`.list` 没了布局 `scrollTop` 读成 0——树自己每次滚动记一份位置，隐藏 / 重挂时靠这份缓存还原，再让 `scrollIntoView({ block: 'nearest' })` 成为 no-op |

## 3. 元素选择

| AC | 验收标准 |
|---|---|
| AC-3.1 | 单击选中元素，显示选中框与元素标签 |
| AC-3.2 | `Shift` + 单击多选；再次 `Shift` 单击已选中的元素则取消它 |
| AC-3.3 | hover 时显示悬停框与标签，不影响已选中项 |
| AC-3.4 | 插件自身的 UI（工具条、面板、评论层）永远不可被选中 |
| AC-3.5 | `Enter` 选中第一个子元素，`Shift+Enter` 选中父元素（层级下钻 / 上浮） |
| AC-3.6 | `Shift+'` **向外扩展**：把父元素加进选中集，原来的子级仍保留（上游语义，不是替换） |
| AC-3.7 | `⌘⇧Enter` 选中当前元素的所有子元素 |
| AC-3.8 | `⌘E` 选中下一个同类元素，`⌘⇧E` 一次选中全部同类 |
| AC-3.9 | `⌘D` 原地复制选中元素 |
| AC-3.10 | `⌘⌥C` / `⌘⌥V` 复制、粘贴样式 |
| AC-3.11 | `Esc` 取消全部选中 |
| AC-3.12 | 选中元素后属性面板出现在元素旁边（见 §5） |
| AC-3.14 | 色盘色值框输入非法颜色时当场回滚成当前色值，不把非法文本留在框里 |
| AC-3.15 | `⌘G` 把选中项包进一个新 `<div>`：外壳插在原位置（兄弟顺序不变），记成「1 条新增 + n 条移动」，一次 `⌘Z` 整体退回 |
| AC-3.16 | `⌘⇧G` 拆掉外壳，子元素按正序回到原容器；外壳若是本次会话造出来的，对消那条新增记录而不是记一条「删除的元素」 |
| AC-3.17 | `⌘C` / `⌘X` / `⌘D` 产出的 HTML 不含编辑器内部记号（`data-selected`、`data-label-id`、`data-vr-*`、`contenteditable` 等）；`data-label-id` 由单调递增计数器发号，粘贴 / 复制出来的副本永不与后来的选中项撞号 |
| AC-3.18 | `⌘X` 走与 Delete 同一条记账通道：删除进改动记录、可从记录里放回、能进提示词；`⌘V` 粘进来的元素记成一条「新增」 |
| AC-3.19 | `⌥Delete` / `⌥Backspace` 清空选中元素的 inline style：每条声明单独进改动记录，一次 `⌘Z` 全部回来；对编辑器注入之后才出现的元素同样有效；焦点在任意输入框内时不接管（保留「往回删一个词」） |
| AC-3.20 | Shift+单击取消其中一个选中项后，后续 hover 不抛异常（被摘掉的把手 / 标签同时从内部数组里剔除） |
| AC-3.21 | ⇧ 点击把元素移出多选后它**真的离开选择引擎**：`unselect(id)` 先按 id 把目标从 `selected` 摘掉再清 `data-*` 属性、再广播（对齐 `unselect_all` 的顺序）；随后的方向键换位、面板改样式、改动列表高亮都不再算上它 |

## 4. 快捷键

分三层，冲突时按这个顺序裁决：

1. **修饰键组合**（`⌘Z` 等）—— 在最前面处理，不受模式影响
2. **本插件的单字母键** —— 仅在工具条可见时归插件
3. **页面自己的键** —— 隐身态下全部放行

| AC | 验收标准 |
|---|---|
| AC-4.1 | `⌘Z` / `⌘⇧Z` 撤销重做（Windows 上 `⌘Y` 也认） |
| AC-4.2 | 在输入框里打字时，单字母键不触发插件功能，字符正常输入 |
| AC-4.3 | 在输入框里 `⌘Z` 让路给浏览器的文本撤销，不撤掉整次改稿 |
| AC-4.4 | 焦点停在插件面板内（例如刚点过工具条按钮）时，单字母快捷键**仍然可用** |
| AC-4.5 | 面板内的 `Tab` 与 `Esc` 归面板（切焦点、关弹窗），不被插件抢走 |
| AC-4.6 | 上游 VisBug 的 13 个工具热键（`g i x l m p a v h d f e s`）已解绑，不会在背后切换工具 |
| AC-4.7 | `L` 开合改动记录、`P` 复制提示词 |
| AC-4.8 | `Delete` / `Backspace` 删除选中元素，且只删一个（不触发上游的重复回调） |
| AC-4.9 | 上游工具条自己的输入框（closed shadow root 内）打字时，单字母模式热键让路，字符原样落进输入框 |
| AC-4.10 | 编辑文案时按一次 `Escape` 退出编辑态（摘掉 `contenteditable` / `spellcheck`、光标离开），第二次 `Escape` 才取消选中；焦点在面板输入框里时 `Escape` 仍是关弹层 / 取消选中 |
| AC-4.11 | 在面板里横向拖数值、越过面板边缘才松手：数值照常算，当前选中的元素不被换掉 |
| AC-4.13 | **修饰键跨平台**：所有快捷键的主修饰键 Mac 上是 ⌘、Windows / Linux 上是 Ctrl（`core/hotkey.js` 的 `isMod`），另一边按着时不算（Mac 上 Ctrl+Alt+V 不触发、Windows 上 ⌘⇧R 不触发）；提示文案按平台显示 ⌘ / Ctrl、⌥ / Alt、⇧ / Shift。按键匹配认物理键位 `e.code`（macOS 上 ⌥ 组合的 `e.key` 是死键字符），`e.key` 只兜底 |
| AC-4.14 | **⌥⌘C / ⌥⌘V 复制、粘贴属性**（Windows Ctrl+Alt+C / V，对标 Figma 的 Copy / Paste properties）：复制取选中元素**全部跟踪属性的计算值**，含 width / height，**不含**位置量（position / left / top / right / bottom / translate / transform / z-index / inset）；同时写一份 `{"visual-revise":"props",…}` JSON 到系统剪贴板，跨标签页也能粘。粘贴范围是选中 + 联动集合，逐条 `applyProp`、一条批次「粘贴属性」、与目标当前计算值相同的跳过（先整份拍下再写，避免前一条改变后一条的计算值）；⌘Z 一次整套退回；toast「已复制 N 项属性」「已粘贴到 N 个元素」，全部相同时提示「已经和复制的一样了」。剪贴板 JSON 只收白名单里的键。焦点在输入框、浏览 / 评论模式、有弹层时不接管；焦点在面板按钮上（刚点完联动）仍接管。上游 VisBug 直接改 DOM 的同名快捷键已解绑 |
| AC-4.15 | **⌘⇧R 剪贴板替换选中元素**（Windows Ctrl+Shift+R，对标 Figma 的 Paste to replace）：剪贴板依次认 HTML（解析出第一个元素）→ 图片（造 `<img src=dataURL>`，锁原元素的宽、高按图片比例算，原元素量不出宽时用图片原尺寸）→ 纯文本（装进 `<span>`）→ 退回内存里最近一次 ⌘C 的副本；每个目标各得一份副本，父子同选只替换最外层。记录复用「新增 + 删除」一对，新增那条带 `replaced {tag, text, identity}`，列表显示「替换」与「原来是 X」，提示词写「替换：把 X 换成 Y」、摘要单列「N 处替换」，删除那段点明是替换的另一半；落点锚点取旧元素的**后邻**（导入时先增后删也稳）；JSON schema 升到 6、导入兼容 1–6，导入后靠 identity 重新配对仍说得出替换。⌘Z 一次整条退回、⌘⇧Z 重做；替换完新元素被选中。条件不满足时**不** preventDefault，浏览器自己的硬刷新照常 |
| AC-4.17 | 三组 Figma 快捷键在**没有选中元素**时不接管（`return false`，浏览器自己的 ⌘⇧R 硬刷新照常）并给一条提示；提示在面板没有目标时自动落到工具条 toast（`shortcutContext().toast` 的回落），不会被静默吞掉。`combo({ mod, alt, shift, ctrl }, key)` 按平台归一化修饰键顺序与连接符（Mac ⌃⌥⇧⌘ 连写、Windows Ctrl+Alt+Shift 加号），所有提示文案与工具条气泡走它（Mac 上「重做」气泡是 Apple 规范序「⇧⌘Z」） |
| AC-4.16 | **⌘⇧C 复制为图片**（Windows Ctrl+Shift+C）：把选中元素连同子元素按屏幕真实渲染截成 PNG 写进剪贴板；多选出**一张**图（所有选中元素外接矩形的并集）。优先走扩展的 `tabs.captureVisibleTab`（页面抛 `visual-revise:capture-request` → content script → service worker → `visual-revise:capture-result`，detail 一律字符串；通道存在与否看 `<html data-visual-revise-capture>`，没装扩展立刻退回 DOM→SVG `foreignObject` 重绘，尺寸仍准但 `<img>` / 背景图 / 伪元素 / shadow 内容不出现）。截图前用一张临时 `!important` 样式表隐藏选中框、把手、参考线、面板、工具条、弹层、批注钉子，截完删掉样式表即恢复；像素比例按「截图宽 / 视觉视口宽」实量，页面缩放与捏合都自然算进去；并集超出视口时 `scrollTo({behavior:'instant'})` 分段截取拼接（fixed 元素会重复出现，已知取舍；超过 24 屏报错），拼完滚回原位。`ClipboardItem` 以 Promise 交 blob 同步发起写入（等 await 完再写用户手势已过期）。service worker 侧每次 `captureVisibleTab` 至少隔 550ms、撞配额退避重试 3 次，非活动标签页如实报错。不进改动记录。toast「已复制 W×H 图片」；没选中时提示先选中 |
| AC-4.12 | 缩放把手写的是 CSS 独立属性 `translate`（不是 `transform`）：进改动记录、进提示词的「定位」段；松手再拖第二次在上一次的位移上累加，不回弹。以前写 `transform` 是整条覆盖页面原有 transform，现在是叠加 |

## 5. 面板摆位

面板固定在一个地方，位置只由用户决定。早先的版本按选中元素的矩形算左右侧，
本意是别盖住正在改的东西，结果每换一个元素面板就跳一次——眼睛每次都得重新
找它，比偶尔被挡住更累。

| AC | 验收标准 |
|---|---|
| AC-5.1 | 属性面板固定出现在同一个位置（默认右上、工具条下方），**不**跟着选中的元素移动 |
| AC-5.2 | 拖动面板后位置记进 `localStorage`；换选元素、关掉面板再打开、刷新页面重新注入，都回到那个位置 |
| AC-5.3 | 任何情况下面板都不会超出视口：拖动时实时夹取，窗口变小后挤回视口内，重新拉大时回到记住的位置 |
| AC-5.4 | 默认位置不与工具条重叠（横排、竖排都是） |
| AC-5.5 | `localStorage` 被禁（无痕窗口 / 站点策略）时读写都不抛，面板退回默认位置照常可用 |
| AC-5.6 | 结构 tab 打开时面板仍在视口内 |
| AC-5.7 | 滚动页面时面板**不**跟着动（它是 fixed 的） |
| AC-5.11 | **网页缩放（⌘+ / ⌘−）或触控板捏合（visualViewport pinch zoom）时编辑器 UI 在屏幕上不变**：属性面板、工具条、改动列表、四个弹层（菜单 / 填充 / 色盘 / 下拉）的屏幕尺寸与位置都不随页面缩放改变。实现：页面放大到 k 倍时这些 fixed 宿主反向 `scale(1/k)`，贴边距离（面板 top 88 / right 16，工具条 top 20，改动列表 top 88 / right 304）除以 k，`max-height` 里的 100vh 乘回 k |
| AC-5.12 | 缩放倍数两条路互为保险：① 扩展进程 `tabs.getZoom` 注入后发一次、`tabs.onZoomChange` 每次变化再发（**不**看 service worker 内存里的 state，它闲置半分钟就被杀），content script 写到 `<html data-visual-revise-zoom>` 并抛 `visual-revise:zoom` 事件；② 页面自己察觉：`devicePixelRatio` 与 `innerWidth` 同时反向变化（±1%）才算缩放，只有 DPR 变是换屏（倍数不变、换锚点），只有宽度变是拉窗口。绝对值以扩展最后一次告知的为锚，没告知过按 1。没有任何扩展消息时（旧 content script、SW 已死）面板也要缩回去。③ 触控板捏合是视觉视口缩放：倍数再乘 `visualViewport.scale`，贴边位置改成贴**视觉视口**的角落（`offsetLeft/Top` + `width/height`），捏合后平移（visualViewport `scroll`）也跟着走；居中的工具条居视觉视口的中线；拖过的记相对视觉视口左上角的屏幕坐标 |
| AC-5.13 | 拖过的面板 / 工具条 / 改动列表记的是**屏幕坐标**（CSS 坐标 × k）：在 150% 下拖到屏幕某处，缩回 100% 或缩到 80% 它在屏幕上还在那一处；`localStorage` 里记的位置同样是屏幕坐标 |
| AC-5.15 | 贴在页面元素上的编辑器物件跟着元素走，但**把手圆点、描边粗细、hover 描边、角标、标签字号、测距线粗细与数字、拖出的参考线粗细**保持屏幕原大：尺寸都乘 `--vr-inv-zoom`（= 1/k，k 含页面缩放与捏合），值写在编辑器自己的 `<style id="visual-revise-zoom-vars">` 里，倍数为 1 时整条规则移除、退出编辑器时清掉；不碰页面的行内样式 |
| AC-5.14 | 缩放原点跟着定位方式走：默认右上角定位以右上角为原点缩，拖过（left / top 定位）以左上角为原点，工具条居中时以顶部中点为原点并保留 `translateX(-50%)`。选中框、参考线、批注钉子这些贴在页面元素上的东西**不**反向缩放 |
| AC-5.16 | 缩放时弹层的**定位、夹取、向上翻**一律按可见尺寸算（宿主布局盒 ÷ 挂上那一刻的 k，`popover-host.js` 的 `visibleSize` / `popoverBounds`），视口边界用视觉视口框：右对齐的菜单右缘始终贴锚点右缘；`vr-select` 下拉的 `minWidth` 写回布局宽（触发器可见宽 × k，且不低于 160px），屏幕上不窄于触发器；Move 工具的抓手（`visbug-grip`，body 直接子元素）也在 `--vr-inv-zoom` 的选择器里。已知取舍：6px 锚点间距、8px 贴边、12px 翻转余量仍是 CSS px |

| AC-5.8 | 工具条可在横排 / 竖排之间切换（第一格那个按钮），选择记在 localStorage，下次注入沿用 |
| AC-5.9 | 竖排时按钮文字收进 hover 气泡，气泡从按钮下方挪到右侧 |
| AC-5.10 | 竖排时分段控件的滑块沿纵轴移动，仍贴合当前模式 |

## 6. 属性面板（逐控件）

面板分 7 组。每个控件操作后必须**立刻**落到元素的 inline style 上，并进入改动记录——
这是整个工具的产出通道，任何一处"看起来改了、其实没写"都是最坏的 bug。

| AC | 验收标准 |
|---|---|
| AC-6.1 | Position：定位下拉写 `position`；X / Y 写 `left` / `top`；旋转写 `rotate`；层级写 `z-index`；X 前缀可横向拖着调值 |
| AC-6.2 | Layout 排列：四个分段各写 `display`（block / flex+column / flex+row / grid）；换行钮切 `flex-wrap` |
| AC-6.3 | 尺寸：W / H 输入写 `width` / `height`；比例锁开着时改 W，H 按锁定时的比例跟着变 |
| AC-6.4 | 对齐九宫格：点 (col,row) 写 `justify-content` / `align-items`，三档为 flex-start / center / flex-end |
| AC-6.5 | 间隔写 `gap` |
| AC-6.6 | 内 / 外边距：两段式输入分别写左右对、上下对；展开钮后四个方向各自可写 |
| AC-6.7 | 裁剪内容：勾上写 `overflow: hidden`，取消是**清掉声明**而不是写 visible |
| AC-6.8 | Appearance：不透明度写 `opacity`，圆角写 `border-radius` |
| AC-6.9 | Typography（**只在直接承载文字的元素上渲染**，见 AC-6.35）：字体下拉只换栈首；字重下拉、字号、行高、字距各写对应属性；对齐四段写 `text-align`；「更多」展开后 `text-transform` / `text-decoration-line` 可写 |
| AC-6.10 | Fill：可增删的**多层**填充列表。`background-image` 收逗号分隔的多层（第一层画在最上），`background-color` 垫底；纯色进不了 image 那一栏，除最底层外一律写成 `linear-gradient(c, c)` |
| AC-6.10a | 每层一行：色块 / 色值 / 不透明度 / 眼睛 / 减号。渐变和图片没有单一色值也没有单层不透明度（CSS 没这东西），那两格对它们只读 |
| AC-6.10b | 填充弹层四格里做三格：纯色 / 渐变 / 图片（只有「从电脑上传」）。**视频不做**——`url(x.mp4)` 语法过得去但画面出不来，`element()` 只有 Firefox 认，真要做只能往元素里插 `<video>` 子层，那是改 DOM 不是改样式 |
| AC-6.10c | 文字色是文本元素的主填充，跟填充层同形、也能用眼睛关掉；但它是 `color` 这条独立属性，删不掉，所以没有减号 |
| AC-6.16 | 每个颜色控件都有**色值**和**不透明度**两个独立输入；改色值不会把已调好的不透明度重置回 100% |
| AC-6.17 | 色盘 / 填充等弹层始终夹在视口内，内容变高（如切到渐变）后重新让位 |
| AC-6.11 | Stroke：颜色 / 宽度 / 样式各写 `border-*`；box-sizing 分段写 `box-sizing` |
| AC-6.11a | 没有描边时是空状态，只剩标题和加号——那三行描述的是一条并不存在的边 |
| AC-6.11b | 描边**只能一条**，加过之后加号置灰。实测 `border-image-source` 不吃逗号多层（写两层整条声明作废），而且它一旦非 none 就取代颜色绘制，跟 `border-color` 也叠不起来 |
| AC-6.12 | Effects：可增删的效果列表，加号弹出七种。三个直接写 CSS 原值的输入框已去掉——一个框里塞着 `rgb(255,255,255) 0 0 0 0, rgba(147,…` 既读不出有几条阴影，也没法单独关掉其中一条 |
| AC-6.12a | 七种的 CSS 落点：内阴影→`box-shadow: inset`、投影→`box-shadow`、图层模糊→`filter: blur()`、背景模糊→`backdrop-filter: blur()`、噪点/纹理→SVG `feTurbulence` 转 data URI 当 `background-image` 的一层、玻璃→`backdrop-filter: blur() saturate()` + inset 高光 |
| AC-6.12b | 同一种可以加多条，填充层和效果列表都可拖拽排序（`background-image` 的层序决定遮挡，`box-shadow` 的多条和 `filter` 的多函数也都有序）。**已知限制**：效果读回的顺序按 CSS 属性分组，跨属性的先后在 CSS 里没有记录、还原不出来；同一条属性内部的顺序保留，而那正是顺序真正影响渲染的地方 |
| AC-6.12b1 | 拖拽用 pointer 事件而不是 HTML5 `draggable`：行里铺满了 `<button>`，按在它上面浏览器根本不发 `dragstart`；而且原生拖放在自动化里驱动不了——CDP 的鼠标事件不会让浏览器合成拖放。指针捕获推迟到越过 4px 才生效，否则会把后续 click 的 target 重定向到整行，色块和参数面板就点不开了 |
| AC-6.12c | 每种效果的参数面板只列 CSS 真的做得到的几项。**Figma 的 Glass 只做得到近似版**：Refraction / Depth / Dispersion / Frost / Splay 是它渲染器里的折射运算，CSS 没有任何东西对得上；Shader 需要 WebGL 或 Houdini，不做 |
| AC-6.12d | 噪点/纹理与填充层共用 `background-image`：效果层排在前面（画在填充之上），填充解析时按 data URI 里的记号跳过它们，两边不会互相吞掉 |
| AC-6.22 | Fill / Stroke / Effects 三个分区**空状态也渲染**（标题 + 加号）——加号是添加第一条的唯一入口，整个分区不出现的话用户无从下手 |
| AC-6.23 | 这三个分区标题右侧：加号常驻，「绑定变量」鼠标进标题栏才出现（Figma 的 default / hover 两态）。分区级眼睛下放到每一行 |
| AC-6.23a | 「绑定变量」常驻显示（平时压暗，鼠标进标题栏提亮）。Figma 是 hover 才显形，但它那儿标题栏没有别的按钮；这里藏起来只会在加号左边留一个等宽的空洞，看着像图标没加载出来 |
| AC-6.23b | 在收起的分区上点加号会自动展开——加了东西却看不见，点下去像是没反应 |
| AC-6.23c | **Effects 标题栏没有「绑定变量」**，只有 Fill / Stroke 有。效果模型是从 computed 反解出来的（`parseEffects` 读的是解析后的值，`parseShadow` 的颜色正则还刻意排除了后面跟括号的 token），`var()` 存不住，绑上去活不过一次编辑 |
| AC-6.24c | 绑了变量的格子换成一整块 chip（圆点 + 变量名），不再有可编辑的色值和不透明度。填充层的 chip 就是那一层 `vr-fill` 的触发器（弹层是实例方法，行里没有实例的话 chip 点了无处可去）——绑了变量，色值就该去改那个变量。判定读**声明原文**而不是 computed：`getComputedStyle` 会把 `var()` 解析成最终颜色，从它身上看不出绑定 |
| AC-6.24d | chip 右侧是 unlink；点它用当前解析出的实际颜色顶替 `var()`——绑定断开、画面不变，这是 Figma 那个 unlink 的语义，不是「清空这一格」。填充层走 `data-unlink-layer`，只解那一层：走 `#unlink(prop)` 会把整条 `background-image` 拍平成一长串解析值，别的层跟着遭殃 |
| AC-6.24e | 变量页按值的类型过滤：挑颜色时只列颜色变量，字体栈、`12px`、纯数字都不出现——点了也 apply 不上，只是让人在几十项里多翻几屏 |
| AC-6.24f | **样式表里的 `var()` 也算绑定**。绝大多数页面的变量引用写在样式表里（`.card { background: var(--surface) }`），只读 inline 会把它们全当成死色值。`core/cascade.js` 把命中元素的规则铺平，按 important / inline / @layer / 优先级 / 顺序挑出这条属性的层叠赢家，赢家是 `var()` 就显示 chip；简写里的一段（`border: 1px solid var(--line)`）也认，只要整条简写里只有这一个 `var()` 且解析出来是颜色。chip 的 title 写明来源规则 |
| AC-6.24g | 字色会继承：`<p>` 自己没写 `color`，字色来自祖先的 `var(--ink)` 时也显示 chip，title 注明「继承自 `<div#x.card>`」。Figma 没有继承，但用户看到的就是「这段字的颜色来自那个变量」 |
| AC-6.24h | 被更高优先级的**非变量**声明压掉的不显示 chip。层叠判定是近似的（`@layer` 里 important 的反转、`@container` 条件没做），所以还有一道保险：挑出来的变量解析出的颜色必须等于 computed，对不上就当没绑定——宁可显示色值，也不显示一个错的变量名 |
| AC-6.24i | **点 chip 重开变量页**换绑：当前绑定的那项勾着，挑别的就把 inline 写成新的 `var()`，chip 跟着换（写入顺序是「关弹层 → `#commit` → `render()` → toast」——`#commit` 对颜色属性不触发重绘，不显式 render 格子就不会变成 chip）。弹层贴 chip 左缘（chip 在行的最左边）；标题栏那个「绑定变量」按钮的弹层仍贴右缘 |
| AC-6.24j | 变量页的行：**最左一个 16px 色圈**直接看颜色（Figma 的变量列表就是这样），然后变量名、色值，**对勾在最右**——左边已经有色圈，勾再挤在最左就成了两列图标。色圈的颜色从选中元素身上读（不是 `:root`）：同一个变量可能在某个容器里被重新赋值 |
| AC-6.24b2 | `Esc` 能关掉弹层。面板的 Esc 分支只是「有弹层时让路」，让完之后原先没有人接手 |
| AC-6.25 | `vr-select` 下拉（字体等长列表）：在下拉内滚动不关闭、滚到底能点到最后一项、选中写回触发器、Esc 关、点弹层外关。上下键移动高亮、Enter 选中——字体列表几百项，没有键盘只能拖滚动条一个个找 |
| AC-6.26 | `openMenu` 菜单同上（打开 / 在视口内 / 菜单内滚动不关 / 选中生效并关闭 / Esc）。变量列表已经搬进颜色弹层的「变量」页，`openMenu` 现在的消费者是 **Effects 添加菜单**与尺寸模式菜单，这条挂在前者上验 |
| AC-6.29 | **Esc 一次只做一件事**：有弹层时第一下关弹层、选中保持；第二下才取消选中。以前弹层组件不接 Esc，一路走到取消选中、弹层跟着面板被动消失——看着像关了，其实是选中没了 |
| AC-6.27 | 色盘：Esc 关、点弹层外关、在色盘上滚动不关。**焦点在色盘的输入框里时 Esc 也要关**——面板那句「有弹层就让路」让完之后原先没人接手 |
| AC-6.28 | 填充弹层同上；切到渐变后变高仍在视口内 |
| AC-6.30 | **页面 CSS 漏不进弹层**。菜单 / 填充 / 色盘 / 下拉四个弹层挂在页面 body 上（属性面板 overflow:auto，放在里面会被裁掉），以前内容直接暴露给页面样式：弹层里的 tab 条叫 `.tabs`，页面恰好也有 `.tabs { border-bottom }`，那条线就漏进来了；`* { box-sizing }` 有的站有、有的站没有，输入框就时而 28 时而 30。现在宿主行内 `all: initial` 打头、内容包进 shadow root，页面的类名 / 元素 / 通配 / body 继承规则都碰不到；`box-sizing: border-box` 和 `button/input { font: inherit }` 自己带（adoptedStyleSheets，`innerHTML` 冲不掉）。宿主上 `keydown` 止步——按键冒到 document 时目标已是宿主 div，hotkeys-js 认不出「在打字」，Enter 会变成「进入子元素」、清空输入框会变成「删除元素」 |
| AC-6.31f | **已绑定的格子从 chip 打开的弹层没有「自定义 \| 变量」页签**，只有变量列表、当前项勾着。绑了变量，色值就不该在这里改——要改颜色先 unlink，unlink 之后从色块打开才有两页。填充层同理 |
| AC-6.36a | Stroke 的颜色行照 Fill 的层行：右侧有隐藏（眼睛）和移除（减号）两个按钮，同一套图标、同高、1:1；有描边时标题栏加号禁用 |
| AC-6.36b | 点眼睛隐藏描边：写 `border-color: transparent` 而不是 `border-style: none`——none 会把边框宽度一起收掉、盒子变小页面跳一下，而且会被当成「没有描边」整行消失、连恢复的入口都没了。宽度 / 样式不动，行压暗，颜色框（或 chip）仍显示原来的颜色 |
| AC-6.36c | 再点眼睛恢复：颜色回到原值，inline 原样（原本没有 inline 的仍然没有） |
| AC-6.36d | 点减号移除描边：整组一起走（CSS 的 border 只有一层）——`border-style: none; border-width: 0`，inline 的 `border-color` 清掉，分区退回空状态、加号可点；进改动记录 |
| AC-6.36e | 移除后 `⌘Z` 一次整组回来；撤销 / 重做 / 导入这类外部改动让 Stroke 从空状态长出行（或反过来）时面板整块重绘，而不是停在旧结构上 |
| AC-6.24b | 在变量列表内部滚动不会把弹层关掉。全局的 `scroll` 监听在 capture 阶段收所有滚动，包括菜单自己的；变量列表有几十项、自带滚动条，一滚就关等于只能选到最上面几项 |
| AC-6.24 | 绑定变量写的是 inline `var(--x)`，压过样式表里原有的引用；改动记录和导出的提示词里存的都是 `var(--x)` 原文而不是一个死色值 |
| AC-6.13 | 以上每一次写入都进改动记录（记录数递增），且面板标签变成"已改"色 |
| AC-6.14 | 分组标题上的「重置本组」只在该组改过时出现，点了把本组全部还原；「临时关闭本组」可开关 |
| AC-6.15 | Effects 默认折叠，减少首屏噪音；Typography 只在渲染得出来的时候出现（AC-6.35），选中**文字元素**时自动展开 |
| AC-6.18 | 「临时关闭本组」关掉的属性跟着该组**这次真的渲染出来的字段**走：选中直接承载文字的元素时 Fill 首行是字色，关组要连字色一起关（只关背景等于没关，这类元素本就没有背景）；纯容器则不动 `color`——那一行没渲染，且 `color` 会继承进整棵子树 |
| AC-6.19 | 填充控件在**纯色**态下与文字色控件同形：色值、不透明度两个可直接编辑的输入，色块与输入框尺寸逐项相同；其余三态（无填充 / 渐变 / 背景图）没有单一色值可填，退回只读摘要标签 |
| AC-6.20 | 颜色类控件点输入框是敲值、不弹色盘（事件跨 shadow 边界会把 `target` 重定向到 host，得看 `composedPath`）；点色块才开弹层 |
| AC-6.21 | 面板里每个图标按钮的图标在按钮方框内水平垂直都居中（`<button>` 的 UA `padding: 1px 6px` 必须显式清掉，否则 border-box 下内容盒被压窄、图标溢出后居中退化成左对齐） |

## 7. 内容操作

改的不只是样式：文案、图片、元素本身的去留和位置，都要能改、能记、能撤、能导出。
「位置」是真的搬 DOM 节点，不是写 CSS `order`——后者只改视觉顺序，DOM 顺序不变，
键盘 Tab 与读屏顺序会和用户看到的对不上，跨父级更是做不到。

| AC | 验收标准 |
|---|---|
| AC-7.1 | 文案：进入编辑态后键入，改动作为「文案改动」单独记录，不混进样式属性；撤销可回到原文 |

| AC-7.12 | 激活会自己吃鼠标的上游工具（Position / Move）时，页面拖拽不接管指针，工具的鼠标交互正常工作 |

| AC-7.13 | 选中元素后按 ↑ / ↓ 在**同一个父级**里换一位（↑ 到前一个兄弟之前，↓ 到后一个兄弟之后）；已在头 / 尾时不动、不记；不跨容器。走 `moveElement`：进改动记录（同一元素反复挪只留一条）、`⌘Z` 退回、导出里有这条移动；选中不变，选中框与结构树高亮跟着走。焦点在输入框、有弹层开着、上游用方向键的工具（Position / Move / Margin…）激活时不接管；多选各自挪一位，相邻都选中时按边界处理不互相换位 |

## 8. 记录与导出

工具的终点是一段 AI 能拿去改源码的提示词。记录必须完整、可回退、可带走。

| AC | 验收标准 |
|---|---|
| AC-8.1 | 改动记录列表：按元素分组，属性 / 文案 / 评论 / 删除各自有计数；hover 列表项在页面上高亮该元素 |
| AC-8.2 | 单条撤销：列表里可撤销某一条属性改动，其它改动不受影响 |
| AC-8.3 | 撤销 / 重做栈：不同属性各自入栈；一次拖拽 / 切排列是一个动作，⌘Z 整体退回 |
| AC-8.4 | 评论：评论模式点元素弹输入框，保存后页面出 pin 并编号；点 pin 可编辑；可删除 |
| AC-8.5 | 参考图：评论里可通过选文件 / 粘贴 / 拖拽加图，逐张移除，带说明一起保存 |
| AC-8.6 | 提示词：包含元素定位、属性改动、独立的「文案改动」「移动的元素」「删除的元素」「图片替换」段落，以及摘要计数。移动那一段的 from / to 两头都给出容器选择器 |
| AC-8.7 | JSON：导出带 schema 版本；导入后改动重新应用到页面、记录数一致 |
| AC-8.8 | 跨重渲染：框架把节点整个换掉后，改动一帧内重新找回并施加到新节点；不会贴到长得一样的邻居上 |
| AC-8.9 | 重置：清掉所有记录（含已失联的），页面恢复——包括把搬过家的元素放回原位；⌘Z 能把这次重置连同移动一起救回来 |
| AC-8.10 | 改动记录条目超出可视高度时列表纵向滚动，每行保持自然高度；不得把行压扁到内容被裁掉（× / ↺ 点不到） |
| AC-8.11 | 分组 / 粘贴造出来的新元素在改动记录里单独成行（徽标「新增元素」/ 记录 label），写明加了什么与加在哪个容器的哪个位置；点行可定位选中，↺ 撤掉时对消该条 insert，不留「已删除」假记录 |
| AC-8.12 | 「全部」与「配置」两个计数与 `ChangeStore.stats()` 一致，新增元素计入两者 |
| AC-8.13 | 提示词里有「## 新增的元素」段：用锚点描述位置（在哪个容器里、排在谁之前 / 末尾）并给出精简 outerHTML（超长截断并注明） |
| AC-8.14 | 导出 JSON `schema = 5`，带 `inserts`；导入顺序固定 edits → inserts → moves → removals → comments；`SUPPORTED` 仍收 1–5，旧文件照常导入 |
| AC-8.15 | 「重置全部」之后 `⌘Z` 把文案改动一并救回来（记录数与重置前一致） |
| AC-8.16 | 图片入口（评论参考图 / 换图）执行会话累计上限 20 MB：超出的图被拒并给出可见的 toast，而不是静默丢弃 |
| AC-8.20 | **选中框把手拖改尺寸可撤销**：拖动期间直接写 style（每帧一次），松手后把 width / height / translate 里变了的逐条走 `applyProp` 记进历史栈（一次拖动一条批次，标签「拖改宽度 / 高度 / 位置 / 尺寸」）；⌘Z 退回拖之前的行内值、改动记录里对应条目消失、选中框跟着元素缩回去；⌘⇧Z 重做 |
| AC-8.21 | 改动列表逐条「还原」合成的 `border-radius` / `border-width` 时**逐条长手**各自按快照原文写回或删除（含各自的 important），不对简写整体 `removeProperty`——作者原本只写了一部分的长手不会被抹掉；这次还原本身进历史栈，⌘Z 能再撤回来（已知取舍：对它「重做」会把简写整条写回，画面一致但 inline 不再是作者原来的最小写法） |
| AC-8.18 | **列表跟着选中**：页面上选中元素时，改动列表里这个元素的那组条目持续高亮（蓝边 + 淡蓝底），不在列表可见区就把第一组滚到中间；换选移走，取消选中清掉，多选全亮；列表关着时选中、打开后再高亮并滚到位；记录变化引起的重渲染不抢滚动位置。只做「选中 → 列表」单向 |
| AC-8.19 | 点**评论**条目打开的是那条评论的编辑框（内容、图片都带上），不选中元素、不打开属性面板；其它条目仍是选中元素并滚到它 |
| AC-8.17 | 「新增的元素」记录里的 HTML 反映该元素在页面上此刻的样子（分组的外壳含已搬进去的子元素），而不是它刚被创建那一刻的空壳 |

## 9. 面板 UI 一致性

前面几节都在问「功能对不对」，这一节只问「长得对不对」。功能全绿的界面照样
可以是歪的——本批就是这么抓到「眼睛和减号被挤出面板右边界」的：按钮还在、
点击也有效，只是画到了看不见的地方，所有功能断言都照常通过。

| AC | 验收标准 |
|---|---|
| AC-9.1 | 面板里每个图标都是 1:1（`svg` 的宽高相等、`viewBox` 是正方形），没有被拉扁的 |
| AC-9.1b | 图形本身落在 viewBox 中央（墨迹中心偏移 ≤ 0.6）。这是前一条盖不住的盲区——宽高比和 viewBox 都对，路径照样可以画偏，在 24px 的按钮里就是肉眼可见的歪。量的是 **svg 根节点**的 `getBBox()`：逐个子元素取再合并是错的，那返回各自局部坐标系的边界，外层 `<g transform>` 的平移根本看不见 |
| AC-9.1c | 同一上下文（同一行 / 同一分段 / 同一 acts 组 / 输入框前缀）里图标渲染尺寸一致。现行档位：标题栏与 flow 分段 14、按钮 13、输入框前缀 12。换行钮 13 挤在四个 14 的分段旁边就是小一号 |
| AC-9.1d | 图标墨迹占 viewBox 的 60–80%。同样 13px 的按钮里，眼睛原来画满 88%、加号只画 56%，视觉大小差近一倍；统一后偏小的放大到 10/16，偏大的缩到 12/16 |
| AC-9.2 | 同一行里输入类控件等高。图标按钮不参与——它本来就比输入框矮，Figma 也是这样 |
| AC-9.2b | 同一行里所有控件（含图标按钮）垂直居中，中心线偏差不超过 1px |
| AC-9.2c | 同一个层列表里每行等高 |
| AC-9.2d | 颜色类控件（`vr-color` / `vr-fill`）在面板各处同高——它们在界面上就是同一种东西 |
| AC-9.2f | 所有输入类控件外框统一 **32px、`box-sizing: border-box`**。原来是两套：带 1px 透明边框的（颜色控件 / `resize-cell`）外框 32，不带的（`input` / `segment` / `vr-select`）外框 30——内容高都是 30，差在边框。两套并存时四行并排的按钮列宽跟着差 2px，两列的分界线就错开 |
| AC-9.3 | 同类容器的间距只有一个值，不是每处一个数 |
| AC-9.4 | 没有元素被挤出面板的左右边界（flex 子项缺 `min-width: 0` 时最容易发生） |
| AC-9.5 | 面板与工具条在每个阶段都完整落在视口内，含窄视口 900×640 |
| AC-9.6 | 默认态与选中态的文字、图标都达到 WCAG AA：正文 4.5:1，图标和大字 3:1。半透明前景先合成到底色再算——`opacity: .3` 的灰按钮不能按不透明来判 |
| AC-9.7 | 悬停态同样达标。hover 的颜色写在 CSS 伪类里读不出来，只能真的悬上去再量 |
| AC-9.2e | 并排的图标按钮是**正方形**——只拉高不拉宽会得到 24×32 的长方形，比不拉更难看；宽度用 `aspect-ratio: 1` 跟着行高走 |
| AC-9.9 | 面板左右内边距对称，滚动条不占位。原生滚动条会占 10px 布局宽度把右边挤窄；headless 用 overlay 滚动条量不出，用户的 macOS 一开「始终显示滚动条」就露馅。设计工具面板惯例不显示常驻滚动条 |
| AC-9.10 | 并排行内的间距只有一个值（6px）。原来 grid 行 8、flex 行 6、层列表 4 三种混用，上下两行的间距一眼看得出不一样 |
| AC-9.11 | 每行最右的控件贴到行容器右边缘、不溢出。grid 行的按钮列写死 `24px` 时，按钮被 `aspect-ratio` 拉成 30/32 就探出网格 6~8px，右边缘跟上一行对不齐；改 `auto` 跟着行高走 |
| AC-9.8 | 七种效果的参数面板逐个打开检查：弹层内无元素越界、各行输入区的左右边缘对齐成一列、输入框里的值不被框宽截断（量 `scrollWidth`）、弹层自身在视口内 |
| AC-9.12 | 拆分网格（四角 / 四边）与上面那一行用同一套三列模板（两列 + 按钮列，第三列留空），每一格与上一行两个输入框的左右边缘对齐（±0.5px）；两列铺满整行的话右列会伸到按钮底下、左列比上面的框宽 |
| AC-9.13 | 全局间距 **4px**：同行控件之间、层列表行之间、拆分行与展开网格之间都是 4px（原来 6px）；字段行距（`.rows` 12px）与标签到框（5px）不在此列 |

检查覆盖四个场景：属性 tab 全部展开、填充两层 + 效果四条、结构 tab、窄视口；
外加七种效果的参数面板各开一次。

**由此改掉的**：`--vr-label` 从 `#9b9b9b` 调到 `#a6a6a6`。前者在字段底色 `#383838`
上只有 4.22:1（分段控件未选中项的文字正好落在这个组合上），差一点到 4.5:1；
后者在两种底色上分别是 4.82:1 和 5.74:1。

**检查器的两个坑**（都在注释里记了）：折叠箭头这类元素是 `background: currentColor`
加 `clip-path` 切出来的图形，拿 `color` 当前景会算出 1:1——因为那正是它的背景，
这类空元素要改用自身背景当前景、父级当底色；`opacity` 作用在整个元素上，
等价于把前景按该比例合成到背景，不折算进去会把压暗的按钮判成清晰可见。
